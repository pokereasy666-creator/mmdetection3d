## 0. 为什么要补这一组

#2 的 E3 测量无效，不用于 Q3。原因是执行侧发现的设计缺陷：注入格的 logit 为 30，jitter 后离网络自己的峰值只有一格，于是在 3×3 局部最大值 NMS 中把这个峰值压掉了；而 82.8% 的 GT 原本在 0.5 m 内就有同类初始 query。所以 E3 测的主要是"把放对的 query 挪开一格的代价"，不是"#1 的增益在 ±1 格误差下还剩多少"。只有不做 NMS 的 pedestrian 和 traffic_cone 两类几乎不受影响，这一点构成了内部对照，支持上述判断。

E3 的数值（保留率 −6.36）按字面会判为"C 的前提成立"，而这恰好是事先预测的结论。正因为如此，不能接受这个读数：测量工具本身失效时采纳它，等于用一个无效的数字来确认自己的预测。

E3' 只对**初始化时 0.5 m 内没有同类 query 的 GT** 注入（即 B0 的 G1 + G2 + 漏检，约 20398 个，占 17.2%）。已经放对的 G0 目标不动，NMS 冲突只会落在本来就放偏的目标上，这正是想测的替换。

## 5. 预先登记的判读规则（待确认）

**定义**：
- exact_gain = ΔmAP(E3'-exact)，jitter_gain = ΔmAP(E3'-jitter)，均相对 E0，单位 pp。
- **L（定位余量）= exact_gain − 0.300**。0.300 是 #2 E1 的 coverage_orig：E3' 子集包含 E1 的全部漏检目标，注入方式也相同，所以 exact_gain 里约有这么多是覆盖收益。两次 oracle 的增益不严格可加，L 是近似量。
- 保留率' = jitter_gain ÷ exact_gain，只在 exact_gain ≥ 0.5 pp 时计算；负值视为 ≤ 0.3。分子分母都含覆盖收益，而覆盖收益对 ±1 格偏移不敏感，所以保留率'偏高，对"≤ 0.3"的结论是保守的。
- r_0.5（只作描述，不参与判定）= E3'-jitter 在 0.5 m 阈值上的 ΔmAP 贡献 ÷ E3'-exact 在 0.5 m 阈值上的贡献，近似为纯定位的保留率。
- 临界标注沿用 #2：距阈值 ≤ 0.1 pp（保留率' ≤ 0.03）时标注"临界"，结论仍按规则。

| 规则 | 判据 | 结论 |
| --- | --- | --- |
| Q4 C 的余量 | L ≥ 1.0 pp（即 exact_gain ≥ 1.30） | 余量足够，进入 C 方向的文献查重与方法设计 |
| | 0.5 ≤ L < 1.0 pp | 余量勉强，审阅讨论 |
| | L < 0.5 pp | C 方向也关闭，需要重新定题 |
| Q3' 位置依赖 | 保留率' ≤ 0.3 | 增益需要格子级（或更细）的定位精度，C 的前提成立；方法必须修到精确位置 |
| | 保留率' ≥ 0.7 | 只要进入 ±1 格邻域就能拿到大部分增益，C 的前提不成立 |
| | 0.3 < 保留率' < 0.7 | 审阅讨论 |

**判读顺序**：自检全部通过 → Q4 → 只有 Q4 不是"关闭"时才判 Q3'。

## 6. 已知偏差

- **E3'-jitter 的保留率偏高（保守方向）**：jitter 落点若离网络自己的峰值有 2 格，峰值不会被 NMS 压掉，该目标会有两个 query、多一次匹配机会，jitter_gain 因此偏高。这个偏差对"保留率' ≤ 0.3"的结论是保守的。
- **相邻同类目标的连带影响**：注入格的 3×3 窗口里若有另一个同类目标的峰值，该峰值也会被压掉。车辆类中心间距通常远大于 1 格，影响很小；成排停放的两轮车可能受影响。pedestrian 和 traffic_cone 不做 NMS，可作对照。
- **E3'-exact 混有覆盖收益**：子集包含 E1 的漏检目标。Q4 用扣除后的 L 判定；扣除按 E1 的 +0.300 pp 近似，两次 oracle 之间的交互项未计入。
- **oracle 位置只到格子中心**：注入点离真值最远约 0.42 m，并且沿用原始分数。一个能预测亚格子偏移、同时改善分数的方法，理论上可以超过 L，所以 L 本身也是偏保守的上限。
- 结论只针对这一个权重；只用一个随机种子。
